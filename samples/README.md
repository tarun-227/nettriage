# Sample captures

Everything here is synthetic or deliberately broken. No real network traffic was captured.

- `scenarios/`: 35 labelled captures of a simulated six-PC office, each about 60 seconds long. They were
  generated by `generate/scenarios.py` with seed 1. Each `.pcap` has a `.labels.json` with the ground truth: the
  findings a correct analyser must raise, and nothing else.
- `malicious/`: hostile and broken files that test the parser's safety. See
  [malicious/README.md](malicious/README.md).

The captures were written with a 400-byte snap length, like `tcpdump -s 400`. ARP, DNS and DHCP packets are
complete; long TCP payloads are cut (their content is filler). NetTriage takes TCP lengths from the IP header,
so it still analyses these segments correctly.

The negatives are the point. Each one looks like an attack or a fault to a naive detector, for example a failover
that rebinds the gateway's MAC, or an ad blocker answering 0.0.0.0. NetTriage must explain them under "Checked
and ruled out" instead of raising an alarm.

## Regenerating and measuring

```bash
python samples/generate/scenarios.py                    # this folder (seed 1)
python samples/generate/scenarios.py --split holdout    # fresh seeds, for honest accuracy numbers
python eval/run_eval.py eval/generated/holdout
```

The generators need Scapy (`pip install -e "backend[dev]"`). NetTriage itself never uses Scapy.
